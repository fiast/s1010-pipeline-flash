# Skill: работа с роутерами Sercomm S1010 (Ростелеком)

Автоматизация прошивки партии роутеров: стоковая прошивка Ростелекома →
загрузчик Breed → прошивка Wive-NG. Нужно для станда на 60+ роутеров,
где ручной ввод пароля на каждом не масштабируется.

## Три стадии, по адресам

| Стадия | Адрес | Что это |
|---|---|---|
| Сток | `192.168.0.1` | провайдерская прошивка Ростелекома, пароль с корпуса |
| Breed | `192.168.1.1` | загрузчик, веб-консоль без пароля |
| Wive-NG | `192.168.1.1` | целевая прошивка, вход `Admin`/`Admin` |

## Команды

```bash
# Полный цикл с нуля: сток -> Breed -> U-Boot -> Wive-NG -> приёмка
python3 station.py --password 'пароль'

# Если Breed уже залит, начинаем с него
python3 breed_station.py --mac 14:2E:5E:8B:51:BA

# Диагностика роутера, ничего не записывая
python3 breed_station.py --doctor

# Проверить план записи MAC, ничего не трогая на устройстве
python3 breed_station.py --mac 14:2E:5E:8B:51:BA --dry-run

# Приёмка готового роутера: вход + сверка версии, LAN и WAN MAC
python3 check_wive.py
```

Пароль передаётся ключом `--password`, переменной `S1010_STOCK_PASSWORD`
или запрашивается скрыто через `getpass`. В коде паролей нет.

## Главное: правильная последовательность

Порядок именно такой, обратный работает не всегда:

```
сток Ростелекома
  -> читаем MAC, запоминаем
  -> заливаем breed_s1010
  -> ждём запуска Breed на 192.168.1.1
  -> прописываем MAC-адреса в Breed
  -> шьём U-Boot из Breed
  -> вызываем перезагрузку роутера из Breed
  -> получаем доступ в U-Boot (он же на 192.168.1.1)
  -> шьём Wive-NG в U-Boot
  -> ждём прошивки Wive-NG, до 4 минут
  -> тестируем входом в систему: проверяем,
     что прошивка Wive-NG и WAN MAC отображаются верно
```

**Ключевой момент:** Breed и U-Boot живут на **одном и том же адресе**
`192.168.1.1` и различаются только содержимым главной страницы. После
записи U-Boot и перезагрузки на этом же IP приходит уже U-Boot
(`Server: uIP/0.9`, страница «FIRMWARE UPDATE»), а не Breed.

Скрипт различает их функциями `is_breed()` и `is_uboot()` и ждёт нужной
стадии через `wait_for_stage()`. Без этого пайплайн не понимает, куда он
попадёт, и зависает.

Почему нельзя наоборот (сначала прошивка в Breed, потом U-Boot):
после записи U-Boot загрузчик Breed исчезает, и прошивку класть уже некуда —
получается состояние «U-Boot есть, прошивки нет»: роутер мигает оранжевым,
пингуется, но не грузится. Именно так выглядел первый неудачный прогон.

## Ключевой нюанс: какой MAC нужен

Роутер отдаёт несколько адресов, и они **не равны базовому**:

| Адрес | Смещение | Источник |
|---|---|---|
| `...:BA` | **+0** базовый | ARP (фактический L2) |
| `...:BB` | +1 | WLAN 2.4 |
| `...:BC` | +2 | `wifi_mac_address` на странице статуса |
| `...:C4` | +10 | `settings_wan2.wan_mac` |

В Breed пишется **базовый** (`+0`), от него сам скрипт считает `+1` и `+2`.
Поэтому брать `wan_mac` напрямую нельзя — это ошибка на +10.

`read_mac()` читает три источника, каждый приводит к базовому своим
вычитанием и **сверяет результаты**. При расхождении останавливается,
а не идёт дальше с молчаливо неверным адресом.

## Нюансы стокового интерфейса Ростелекома

Выяснено экспериментально, учтено в `stock_stage.py`.

**1. Обязателен заголовок `Accept-Language`.** Без него сервер отвечает
`(null) 400 Bad Request` вместо нормального ответа — на почти любой запрос,
включая `curl` по умолчанию. С браузерным `Accept-Language` всё работает.

**2. Страницы пустые, всё через `./data/*.json`.** HTML строится JavaScript'ом,
поэтому обычный парсинг форм бесполезен. Данные лежат в эндпоинтах вида
`data/settings_wan2.json`, причём эндпоинт = имя страницы.

**3. Пароль не передаётся открытым текстом:**
```
stage1   = HMAC-SHA256("$1$SERCOMM$", password)
LoginPWD = HMAC-SHA256(encryption_key, stage1)
```
Хеш стандартный HMAC-SHA256 — сверено с оригинальным `sha.js` роутера
через node, совпадает до последнего символа.

**4. Ключ шифрования выдаёт сервер** в `data/user_lang.json`, и он **меняется
при каждом обращении**. Брать из исходника `mainFunctions.js`
(`sys_encryption_key = ''`) нельзя — вход вернёт код `"3"` (неверный пароль).
Нужен ключ, полученный непосредственно перед попыткой входа.

**5. Перед входом нужна пауза** `delay_time` из того же json
(у разных роутеров разная, у проверенного — 18 с).

**6. Коды ответа `data/login.json`:** `"1"` успех, `"2"` уже залогинен,
`"3"`/`"4"` неверный логин или пароль.

**7. Загрузка прошивки** — `POST /upload.cgi` с полями `uploadedfile`,
`uploadType=image`, `MAX_FILE_SIZE=102476800`
(форма разобрана в `js/settings_fw_update.js`).

## Нюансы Breed

**Веб-консоль:** `/` (инфо), `/mac.html` (MAC), `/upload.html` (U-Boot),
`/` с полем `firmware` (прошивка), `/reboot.html` (ребут).

**Ребут — токен обязателен:**
```
GET  /reboot.html      -> hidden-поле magic (случайное, меняется каждый раз)
POST /rebooting.html   -> submit=Reboot&magic=<значение из формы>
```
Пути `/reboot` не существует (404). С неверным `magic` Breed отвечает
302, но **не перезагружается**. Успех подтверждаем не кодом ответа,
а фактом — роутер пропал из сети.

**MAC пишется 54 параметрами** в `POST /mac.html` с `submit=Modify`:
три адреса считаются от базового (+0/+1/+2), остальные обнуляются
(`mac1_2`=FF, `mac2_1`/`mac2_2`/`lan_mac`/`wan_mac`=00).

**Доступ к U-Boot после прошивки** — страница «FIRMWARE UPDATE»
(`Server: uIP/0.9`). Если U-Boot записан, а прошивки нет, роутер сидит
на этой странице и мигает оранжевым.

## Диагностика загрузчика

```
ping есть, порт 80 закрыт, ARP-MAC = 00:0c:43:00:00:01
```
`00:0c:43:00:00:01` — дефолтный MAC Breed, значит MAC роутера не
восстановлен. Если ICMP отвечает, а TCP не идёт — httpd не запустился.
Нужен ребут питанием; если не помогло — вход в Breed зажатием Reset
при включении.

## Файлы

| Файл | Назначение |
|---|---|
| `station.py` | полный цикл от стока. Содержит общие функции записи MAC, ребута и загрузки в Breed |
| `breed_station.py` | цикл с уже залитым Breed. Импортирует логику из `station.py` |
| `stock_stage.py` | стоковый интерфейс: вход, чтение MAC, загрузка прошивки |
| `check_wive.py` | приёмка: вход в Wive-NG и сверка MAC |
| `wive-ng-s1010.bin` | целевая прошивка |
| `uboot-s1010-wive.bin` | загрузчик, пишется последним |
| `breed_s1010.img` | загрузчик Breed, заливается в сток |

`station.py` и `breed_station.py` переиспользуют общие функции, а не
копируют их — при правке обновляются оба сразу.

## Порядок прогона роутера

1. Роутер со стоковой прошивкой, питание подано, ждём `192.168.0.1`
2. `station.py --password` — вход, чтение MAC, заливка Breed
3. Ждём Breed на `192.168.1.1`
4. `breed_station.py --mac <прочитанный>` — запись MAC, заливка U-Boot,
   перезагрузка, ожидание U-Boot, заливка Wive-NG
5. Приёмка: логин `Admin`/`Admin`, сверка версии, LAN MAC и WAN MAC

Шаги 2 и 4 разделены намеренно: если заливка Breed провалилась и Breed
не поднялся, есть ручной ребут и попытка продолжить с шага 4, не начиная
прошивку заново.

## Приёмка: что именно проверяется

`check_wive.py` входит в систему (`Admin`/`Admin`), читает
`/adm/sysinfo.js` и выводит:

* версию прошивки (из `statusSDKversion_value`);
* LAN MAC (из `statusLANMAC_value`);
* WAN MAC (из `statusWANMAC_value`, если поле есть в разметке).

Правильный результат — версия вида `9.2.0.RU.31122024`, и MAC, совпадающий
с тем, что был прочитан в стоковой прошивке.
